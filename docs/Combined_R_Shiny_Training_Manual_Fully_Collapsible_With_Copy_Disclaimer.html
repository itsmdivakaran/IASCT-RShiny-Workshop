Introduction to R Shiny

Shiny is an R package that allows users to build interactive web applications directly from R without requiring extensive knowledge of HTML, CSS, or JavaScript.

Shiny applications are widely used for dashboards, analytics portals, clinical trial monitoring, data exploration tools, and business reporting.

Why Use Shiny?

  • Create web applications directly from R code
  • Build interactive dashboards
  • Visualize data dynamically
  • Generate reports and analytics tools
  • Deploy applications internally or externally
  • Support reactive programming

Shiny Architecture

A typical Shiny application consists of three parts:

  1. User Interface (UI)
  2. Server Logic
  3. Reactive Engine

User Interface (UI)

The UI defines what users will see on the screen. 

ui <- fluidPage(
    titlePanel("My First Shiny App"),
    
    sliderInput(
        "bins",
        "Number of Bins:",
        min = 5,
        max = 50,
        value = 20
    ),

    plotOutput("hist")
)

Server Logic

The server contains the application logic and controls outputs. 

server <- function(input, output){

    output$hist <- renderPlot({

        hist(
            mtcars$mpg,
            breaks = input$bins,
            col = "steelblue"
        )

    })
}

Running the App

shinyApp(ui, server)

Reactive Programming

One of Shiny's key strengths is reactivity. Whenever an input changes, outputs automatically update. 

data_filtered <- reactive({

   subset(iris,
          Species == input$species)

})

If the user selects a different species, the filtered dataset updates automatically.

Module 6: Running First Shiny App

A Shiny application is usually made up of three main parts:

  1. User Interface - defines what the user sees.
  2. Server Logic - defines how the application behaves.
  3. shinyApp() - combines the UI and server and runs the application.

Basic Structure of a Shiny App

library(shiny)

ui <- fluidPage(
    # User interface code
)

server <- function(input, output) {
    # Server logic code
}

shinyApp(ui, server)

Complete Example: My First Shiny App

This application asks the user to enter a name and displays a welcome message. 

library(shiny)

#-------------------------
# User Interface
#-------------------------

ui <- fluidPage(

    titlePanel("My First Shiny App"),

        value = ""

# Server Logic
#-------------------------

server <- function(input, output) {

    output$welcome <- renderText({

        if(input$name == "") {

            "Please enter your name."

        } else {

        }

    })

}

#-------------------------
# Run Application
#-------------------------

shinyApp(ui, server)

Module 7: Layouts in Shiny

Layouts control how inputs and outputs are arranged in a Shiny application. Good layouts make applications easier to use and easier to understand.

Common Layout Functions

Layout Function Purpose

sidebarLayout() Creates a sidebar area for inputs and a main area for outputs.
sidebarPanel() Usually contains user input controls.
mainPanel() Usually contains outputs such as plots, tables, and text.

Module 7.1: fluidPage()

The fluidPage() function creates a responsive Shiny page. Components are placed one after another and automatically adjust to screen size.

Complete Example: fluidPage() with mtcars Dataset

This application allows the user to select X-axis and Y-axis variables from the mtcars dataset and creates a dynamic scatter plot. 

library(shiny)

#-------------------------
# User Interface
#-------------------------

ui <- fluidPage(

    titlePanel("MTCARS Explorer using fluidPage"),

    h3("Select Variables"),

    selectInput(
        inputId = "xvar",
        label = "Select X-Axis Variable:",
        choices = names(mtcars),
        selected = "wt"
    ),

    selectInput(
        inputId = "yvar",
        label = "Select Y-Axis Variable:",
        choices = names(mtcars),
        selected = "mpg"
    ),

    sliderInput(
        inputId = "pointsize",
        label = "Point Size:",
        min = 1,
        max = 5,
        value = 2
    ),

    checkboxInput(
        inputId = "showtable",
        label = "Show Data Table",
        value = TRUE
    ),

    hr(),

    h3("Selected Variables"),

    textOutput("summary"),

    h3("Scatter Plot"),

    plotOutput("scatter"),

    h3("Data Table"),

    tableOutput("tbl")

)

#-------------------------
# Server Logic
#-------------------------

server <- function(input, output) {

    output$summary <- renderText({

        paste(
            "The plot displays",
            input$yvar,
            "against",
            input$xvar,
            "from the mtcars dataset."
        )

    })

    output$scatter <- renderPlot({

        plot(
            mtcars[[input$xvar]],
            mtcars[[input$yvar]],
            pch = 19,
            cex = input$pointsize,
            col = "blue",
            xlab = input$xvar,
            ylab = input$yvar,
            main = paste(input$yvar, "vs", input$xvar)
        )

    })

    output$tbl <- renderTable({

        if(input$showtable) {

            head(mtcars)

        }

    })

}

#-------------------------
# Run Application
#-------------------------

shinyApp(ui, server)

What Happens in This App?

  • The user selects variables from the mtcars dataset.
  • The scatter plot changes based on the selected variables.
  • The slider controls the size of the plotted points.
  • The checkbox controls whether the data table is shown.

sliderInput() Controls point size in the plot.

textOutput() Displays selected variable description.

Module 7.2: sidebarLayout()

The sidebarLayout() function is commonly used in dashboards. It separates the application into two areas:

  • sidebarPanel() - usually placed on the left side for inputs.
  • mainPanel() - usually placed on the right side for outputs.

Complete Example: sidebarLayout() with iris Dataset

This application allows the user to select an iris species, control the point size, show a scatter plot, and optionally display a filtered table. 

library(shiny)

#-------------------------
# User Interface
#-------------------------

ui <- fluidPage(

    titlePanel("Iris Explorer using sidebarLayout"),

    sidebarLayout(

        sidebarPanel(

            h3("Input Controls"),

            selectInput(
                inputId = "species",
                label = "Select Species:",
                choices = unique(iris$Species),
                selected = "setosa"
            ),

            sliderInput(
                inputId = "pointsize",
                label = "Point Size:",
                min = 1,
                max = 5,
                value = 2
            ),

            checkboxInput(
                inputId = "showtable",
                label = "Show Data Table",
                value = TRUE
            )

        ),

        mainPanel(

            h3("Selected Species Summary"),

            textOutput("summary"),

            h3("Scatter Plot"),

            plotOutput("scatter"),

            h3("Filtered Data Table"),

            tableOutput("tbl")

        )

    )

)

#-------------------------
# Server Logic
#-------------------------

server <- function(input, output) {

    filtered_data <- reactive({

        subset(
            iris,
            Species == input$species
        )

    })

    output$summary <- renderText({

        paste(
            "You selected",
            input$species,
            "with",
            nrow(filtered_data()),
            "records."
        )

    })

    output$scatter <- renderPlot({

        plot(
            filtered_data()$Sepal.Length,
            filtered_data()$Sepal.Width,
            pch = 19,
            cex = input$pointsize,
            col = "darkgreen",
            xlab = "Sepal Length",
            ylab = "Sepal Width",
            main = paste(
                "Sepal Length vs Sepal Width for",
                input$species
            )
        )

    })

    output$tbl <- renderTable({

        if(input$showtable) {

            head(filtered_data(), 10)

        }

    })

}

#-------------------------
# Run Application
#-------------------------

shinyApp(ui, server)

What Happens in This App?

  • The dropdown filters the iris dataset by species.
  • The slider changes the size of the points in the plot.
  • The checkbox controls whether the filtered table is displayed.
  • The text output summarizes the selected species.
  • The plot and table update automatically when the user changes inputs.

Important Layout Components

Component Description
sidebarLayout() Creates a two-part layout with sidebar and main panel.
sidebarPanel() Holds user inputs such as dropdowns, sliders, and checkboxes.
mainPanel() Holds outputs such as text, plots, and tables.
reactive() Creates a dataset that automatically updates when input changes.

Comparison: fluidPage() vs sidebarLayout()

Feature fluidPage() sidebarLayout()
Purpose Creates a responsive page layout. Creates a sidebar and main output area.
Best Used For Simple apps, forms, and custom layouts. Dashboards and analytical apps.
Input Placement Inputs can be placed anywhere on the page. Inputs are usually placed in sidebarPanel().
Output Placement Outputs can be placed anywhere on the page. Outputs are usually placed in mainPanel().
Beginner Friendly Yes, very simple to start with. Yes, especially useful for dashboard-style apps.

Reactive Programming

Reactive programming is the foundation of Shiny applications. A reactive application automatically updates outputs whenever inputs change, without requiring manual refreshes.

Reactive programming enables Shiny applications to respond dynamically to user inputs and changing data.

Reactive Components

  • reactive()
  • observe()
  • observeEvent()
  • eventReactive()

1. reactive()

A reactive expression creates a value that automatically updates whenever its dependent inputs change.

When to Use reactive()

  • Data filtering
  • Calculations
  • Reusable business logic
  • Data transformations

Reactive Dependencies

Reactive dependencies define how information flows through a Shiny application. Whenever a reactive input changes, all dependent reactive expressions and outputs are automatically updated.

Understanding reactive dependencies helps developers build efficient applications that avoid unnecessary calculations and improve performance.

What is a Reactive Dependency?

A reactive dependency exists when one reactive component depends on another. Shiny automatically tracks these relationships and updates only the parts of the application affected by a change.

        ifelse(
            STUDY == "Diabetes",

    ifelse(
        SUBGROUP == "Female",

        0
    )

)

study_data$SITE_COUNT <- with(

    study_data,

        STUDY == "Oncology",

filterUI <- function(id){

    ns <- NS(id)

    tagList(

        h3("Filter Controls"),

        selectInput(

            inputId = ns("study"),

            label = "Select Study",

            choices = unique(
                study_data$STUDY
            )

        ),

        selectInput(

            inputId = ns("subgroup"),

            label = "Select Subgroup",

            choices = unique(
                study_data$SUBGROUP
            )

        ),

        actionButton(

            inputId = ns("refresh"),

            label = "Refresh Dashboard"

        )

    )

}

filterServer <- function(id){

    moduleServer(

        id,

        function(input, output, session){

            observeEvent(input$refresh, {

                showNotification(

                    paste(
                        "Dashboard refreshed for",
                        input$study,
                        "-",
                        input$subgroup
                    ),

                    type = "message"

                )

            })

            return(

                list(

                    study = reactive({
                        input$study
                    }),

                    subgroup = reactive({
                        input$subgroup
                    })

                )

            )

        }

    )

}

metricsUI <- function(id){

    ns <- NS(id)

    tagList(

        h3("Enrollment Metrics"),

        tableOutput(
            ns("metrics_table")
        )

    )

}

metricsServer <- function(id, filtered_data){

    moduleServer(

        id,

        function(input, output, session){

            output$metrics_table <- renderTable({

                validate(

                    need(

                        nrow(filtered_data()) > 0,

                        "No records available for selected filters."

                    )

                )

                data.frame(

                    Metric = c(

                        "Total Enrollment",

                        "Average Monthly Enrollment",

                        "Maximum Monthly Enrollment",

                        "Total Site Count"

                    ),

                    Value = c(

                        sum(
                            filtered_data()$ENROLLMENT
                        ),

                        round(
                            mean(
                                filtered_data()$ENROLLMENT
                            ),
                            2
                        ),

                        max(
                            filtered_data()$ENROLLMENT
                        ),

                        sum(
                            filtered_data()$SITE_COUNT
                        )

                    )

                )

            })

        }

    )

}

trendServer <- function(id, filtered_data, selected_study, selected_subgroup){

    moduleServer(

        id,

        function(input, output, session){

            output$trend_plot <- renderPlotly({

                validate(

                    need(

                        nrow(filtered_data()) > 0,

                        "No data available for trend analysis."

                )

                plot_ly(

                    data = filtered_data(),

                    x = ~MONTH_NUMBER,

                    y = ~ENROLLMENT,

                    type = "scatter",

                    mode = "lines+markers",

                    color = I("steelblue"),

                    text = ~paste(

                        "<br>Subgroup:", SUBGROUP,
                        "<br>Month:", MONTH,
                        "<br>Enrollment:", ENROLLMENT,
                        "<br>Sites:", SITE_COUNT
                    ),

                    hoverinfo = "text"

                ) %>%

                layout(

                    title = paste(
                        "Enrollment Trend -",
                        selected_study(),
                        "-",
                        selected_subgroup()
                    ),

                    xaxis = list(

                        title = "Month",

                        tickmode = "array",

                        tickvals = 1:12,

                        ticktext = month.abb

                    ),

                    yaxis = list(
                        title = "Enrollment"
                    )

                )

            })

        }

    )

}

downloadServer <- function(id, filtered_data, selected_study, selected_subgroup){

    moduleServer(

        id,

        function(input, output, session){

            output$download_report <- downloadHandler(

                filename = function(){

                    paste0(

                        selected_study(),

                        "_",

                        selected_subgroup(),

                        "_study_report.csv"

                    )

                },

                content = function(file){

                    write.csv(

                        filtered_data(),

                        file,

                        row.names = FALSE

                    )

                }

            )

        }

    )

}

#=========================================================
# Main Server
#=========================================================

server <- function(input, output, session){

    #----------------------------------
    # Call Filter Module
    #----------------------------------

    filters <- filterServer(
        "filters"
    )

    #----------------------------------
    # Shared Reactive Dataset
    #----------------------------------

    filtered_data <- reactive({

        subset(

            study_data,

            STUDY == filters$study() &
            SUBGROUP == filters$subgroup()

        )

    })

    #----------------------------------
    # Call Other Modules
    #----------------------------------

    metricsServer(

        "metrics",

        filtered_data

    )

    trendServer(

        "trend",

        filtered_data,

        filters$study,

        filters$subgroup

    )

    studyTableServer(

        "table",

        filtered_data

    )

    downloadServer(

        "download",

        filtered_data,

        filters$study,

        filters$subgroup

    )

}

Why This is an Enterprise Pattern

This modular pattern is useful for large enterprise Shiny applications because each module has a clear responsibility. Developers can modify the filter module, metrics module, chart module, table module, or download module independently.

This structure also makes it easier to extend the application with additional modules such as:

  • Safety Dashboard Module
  • Efficacy Dashboard Module
  • Data Quality Module
  • Patient Listing Module
  • Site Performance Module
  • Report Generation Module
